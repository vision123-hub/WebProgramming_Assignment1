Week 10_2: GitHub Pages

GitHub Pages publishes a static website from a GitHub repository. This exercise uses the existing WebProgramming_Assignment1 repository; it does not create another repository or move any coursework.

1. Configure Pages and publish the website

This course website is published from the repository's main branch and repository root. Its project-site address is https://vision123-hub.github.io/WebProgramming_Assignment1/. A project site includes the repository name in its URL, so files should use relative paths such as week%2010_2/github-pages.html.

  1. Open the repository on GitHub and select Settings, then Pages.
  2. Under Build and deployment, choose Deploy from a branch, select main and /(root), then save.
  3. Wait for the Pages deployment in the repository's Actions tab to complete, then open the published site URL and check the page and its navigation.

Pages is already serving the existing course site. These Week 10 additions are local until they are committed and pushed to main; deployment of these changes and the live checks below must therefore happen after publishing them.

2. Request a missing page

A URL that does not match a published file should return an HTTP 404 Not Found response. Before adding a custom page, test a deliberately nonexistent path in a browser and note the hosting provider's default not-found response.

curl -i https://vision123-hub.github.io/WebProgramming_Assignment1/this-page-does-not-exist.html

Check both the response status and the page body. A useful not-found page should explain the problem and give visitors a working route back to the site.

3. Create and deploy a custom 404 page

GitHub Pages automatically uses a file named 404.html at the published root for missing paths. This repository includes a custom page with a clear message and links back to the homepage and assignments. Relative links work under the repository's project-site path.

git status --short
git add 404.html
git diff --cached
git commit -m "Add a custom GitHub Pages 404 page"
git push origin main

After the push, wait for the Pages workflow to finish. Then request a different nonexistent URL and verify that the custom content appears while the HTTP response remains 404 Not Found. The file itself can also be opened directly at .../404.html; that direct file request returns 200 OK, so it does not replace testing an actually missing URL.

The commands above are an example of a direct push. For the class pull-request workflow, publish a feature branch and merge it into main through a reviewed PR instead. Do not stage unrelated existing work.

4. Reflection

GitHub Pages provides hosting for static files directly from a repository. Testing a real missing URL confirms both the status code and the user experience; a branded 404.html helps visitors recover without hiding that the requested page was not found.
